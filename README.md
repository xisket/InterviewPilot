# Interview Companion for Windows

A native WPF desktop starter application with two modes: mock interview practice and assistance during interviews where AI use and sharing the interview content are permitted.

## Focus appearance

The Focus workspace uses a persistent sidebar for **Mock practice**, **Live assistance**, **CV & job**, and **AI settings**. Import résumé files and edit role/job context under CV & job; ATS results open in the workspace Response tab. The header's **Dark theme** switch updates the whole app immediately, including inputs, panels, and response/prompt views. Light is the default. The preference is saved separately in `%LOCALAPPDATA%\InterviewCompanion\appearance.json` and restored at startup. Button labels remain black in both themes.

## Run

Requires Windows and the .NET 10 Desktop Runtime (or the .NET 10 SDK for building).

```powershell
dotnet run --project InterviewCompanion.csproj
```

Build a portable, framework-dependent Windows application:

```powershell
dotnet publish InterviewCompanion.csproj -c Release -o dist
.\dist\InterviewCompanion.exe
```

## Use

1. Enter a target role, job description, and relevant experience under **CV & job**. These fields save locally for future sessions.
2. Choose **Mock practice**. Answer the displayed question, request feedback, and advance through the question bank. A configured AI service supplies tailored questions and feedback.
3. Choose **Permitted live assistance**, confirm permission, and paste an interviewer question. Click **Answer** to call the configured AI for a short first-person draft (requested as 2–4 sentences, up to 90 words), or **Suggest talking points** for an outline. Answer requires an AI connection and uses your résumé context without inventing personal achievements. Review generated drafts for accuracy. Always-on-top is optional.
4. Export completed question/answer/guidance entries to Markdown before closing. Unsaved sessions are lost on exit. Clear session resets history but keeps the profile fields.

The optional AI connection accepts a complete chat-completions-compatible endpoint URL, model name, and optional bearer key, including a compatible local model server. It expects `choices[0].message.content` in the response. Remote services must use HTTPS; HTTP is allowed only for loopback endpoints. Check the chosen provider's API schema and data policies. Some models require additional request parameters and are not compatible with this initial client.

AI connection settings automatically save after edits and reload on startup. The endpoint and model are stored in `%LOCALAPPDATA%\InterviewCompanion\ai-settings.json`; the API key is encrypted with Windows DPAPI for the current Windows user. Clearing the API-key field also clears the saved key. CV, role, job description, library documents, and library preferences save in `context-library.json` in the same folder as readable local text; interview sessions are not automatically saved. A request sends the role, résumé text, job description, current input, and up to four recent session entries to the configured service. Local loopback requests also include enabled library reference documents and the configured assistant instructions; remote requests do not include reference-library documents. No guidance request is made until you click an AI action with an endpoint configured. Provider charges may apply. Session export includes submitted interview content, but does not include the API key.

## Guided Ollama setup and persistent context

Open **AI settings** and expand the numbered sections:

1. **Set up Ollama locally** shows the exact PowerShell commands and provides run buttons to install using WinGet, start the server, download the chosen base model, and check installed models. Installation requires internet access and enough disk space; a model download can be several GB. If WinGet is unavailable, install from [Ollama for Windows](https://ollama.com/download/windows). The command runner checks the usual user-install executable path after installation, so reopening the app to refresh PATH is generally unnecessary. Start is idempotent when the server already responds. Commands are generated by the app, not editable shell scripts; model names are validated before being placed in commands. Output and a cancellation button are visible. A separately launched installer or server can outlive a cancelled command.
2. **Persistent CV and document library** supports CV import and PDF, DOCX, TXT, or Markdown references (up to 30 documents, each at most 50,000 extracted characters; text files must be under 200 KB). Imports start disabled. Select each reference to inspect/edit its name and extracted text, enable it, and click **Save selected document**. You can remove documents without modifying their source files. CV, job/role context, instructions, and context limits save automatically; document editor changes require the save button. Reference questions are distinguished from candidate experience. **Preview enabled context** displays the full system prompt constructed from the current saved library. Context over the selected character budget is rejected explicitly. The token-window setting is applied to the saved personal model during sync; character counts are not an exact token estimate.
3. **Save and inspect your personal Ollama model** creates or updates the selected name (default `interview-companion:latest`) from your base model using Ollama's local `/api/create`. Its system prompt contains the selected CV and reference context; `num_ctx` is set to your chosen window. The base and personal names must differ. **Sync to Ollama** selects the new model in the app. **Inspect saved Ollama model** reads the actual `/api/show` metadata, including its saved system prompt, parameters, and generated Modelfile. This is persistent prompt configuration, not model-weight training or an embedding database. Other Ollama clients must select this model and retain its system prompt to use the snapshot. The Interview Companion app supplies its current configured context as the system message when requesting local guidance.

Library changes affect subsequent local app requests immediately after saving. They update Ollama's stored model snapshot only when you sync again. Removing/disabling a document in the library does not erase previously saved model snapshots: sync the same personal-model name to replace its context. Renaming the personal model leaves the previous model intact. The setup and sync tools target `http://localhost:11434`; normal app inference still uses the endpoint in the AI connection fields.

Integration checks against an installed local `llama3.2:3b`: `dotnet run --project checks/ParserChecks.csproj -c Release -- --ollama-management`. These create, inspect, and remove a uniquely named temporary model containing only synthetic context; they do not install software or alter your personal model.

Local loopback endpoints have a five-minute request timeout and a 384-token output limit to keep local coaching concise (longer replies may be cut off). Remote endpoints have a 90-second timeout. The status bar shows elapsed time, and cancellation is reported separately from timeout. If a local request times out, try shorter résumé/job context or a smaller model; increasing the timeout does not guarantee a fast response.

The **Prompt** tab displays the exact last AI request body, including instructions and résumé/job context, in a selectable read-only view. It excludes authorization headers and the API key, updates when a request starts, and clears with the session. Responses stream into the **Response** tab as generated (compatible servers must support chat-completion SSE streaming or return a normal JSON completion). Interrupted output is labeled incomplete. Local **Answer** drafts use a 180-token cap and omit past session entries to reduce prompt work and avoid treating earlier drafts as facts; role, job, résumé, and the current question are still included. Streaming reduces the wait to see text; total generation time still depends on model, hardware, and prompt size.

## Current scope

Without an AI connection, practice uses a fixed question bank and explicitly labeled word-count/structure checks. Live assistance supplies a general response framework. These are not semantic evaluations. With a compatible service, question generation, feedback, and talking points use the supplied context.

This version supports typed/pasted input and explicit playback-audio recording for local transcription, as described below. Windows dictation (Windows + H) can enter microphone speech in the input box if available and configured on the machine. It does not identify individual speakers or synthesize an interviewer voice. No stealth or screen-share concealment is implemented. An installer remains future work.

## Transcribe interviewer from computer audio

In **Permitted live assistance**, confirm interviewer permission and click **Transcribe interviewer**. First use downloads the multilingual Whisper tiny model (~75 MB) to `%LOCALAPPDATA%\InterviewCompanion\models`. After setup, a visible **RECORDING COMPUTER AUDIO** indicator shows the default Windows playback device. Click **Stop & transcribe** when the interviewer finishes. Capture stops automatically after two minutes. The local Whisper engine processes the captured audio and appends the transcript to **Interviewer question**, preserving existing text. Review/correct it before clicking **Answer**; transcription never requests an answer automatically.

Capture uses Windows WASAPI loopback through NAudio: it records all audio on the default multimedia output device, including notifications and any other speakers in the call. It does not access the microphone or isolate the interviewer. Configure the meeting to use the Windows default playback device before recording, and mute other apps. A device switch during recording requires stopping and restarting capture. **Cancel request**, revoking permission, or closing the application stops capture. Cancelled or failed transcription preserves the existing question. Captured audio is held in memory and not written to disk or uploaded; the transcript is only sent to the configured AI when you subsequently request guidance.

Recognition works without Ollama or an API key after the model download. It runs on CPU and may take time; tiny favors speed over accuracy, especially for names, accents, noisy audio, and technical terms. Windows must support the bundled Whisper runtime (x64 CPU with AVX/AVX2 support) and audio conversion. Silence and very short clips are rejected. Recording is explicit start/stop, not continuous live captioning.

## CV import and ATS-style checks

Use **Import CV · PDF / Word** to extract a PDF or `.docx` locally into the editable résumé field. Confirm replacement if text is already present. PDF extraction uses [PdfPig](https://github.com/UglyToad/PdfPig); Word extraction reads OOXML paragraphs and tables in the main document body, excluding deleted text. Headers and footers are excluded. Save legacy `.doc` files as `.docx` first. Image-only PDFs require OCR outside this application. Limits: 20 MB, 50 PDF pages, and 50,000 extracted characters. Reading order may need correction for complex layouts.

Import automatically shows a local ATS-style review. **Run ATS-style check** reruns it after editing the résumé or job description. The report detects email addresses, possible phone numbers, English/Spanish section indicators, and literal job keyword matches. It is a transparent heuristic, not an external ATS integration, semantic assessment, or hiring score. Keyword selection excludes common stop words and compares up to 35 terms, prioritizing repeated terms. Only add skills you actually have. Import and review do not send data to the AI endpoint; subsequent AI guidance includes the edited résumé text as documented above.

Parser regression checks: `dotnet run --project checks/ParserChecks.csproj -c Release`.

## Validation

Build with `dotnet build -c Release`. End-to-end AI behavior requires a configured compatible service and credentials. Do not claim these integrations are verified just because the app compiles.
